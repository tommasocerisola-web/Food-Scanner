# Food Scanner for Android

This is the Android packaging of Food Scanner: a standalone APK, without Termux
and without a server to start by hand. The app contains:

- the same web UI as the desktop version;
- the Python scoring engine;
- the table of 546 additives;
- the offline demo;
- the Open Food Facts client.

Everything runs **inside the app**: the WebView opens `127.0.0.1` and the Python
server listens only on the phone loopback.

## Requirements

- Android 17 (API 37) or higher;
- an **arm64** phone;
- an Internet connection to look products up on Open Food Facts;
- no account, no key and no Termux.

The APK is built with `compileSdk 37.0`, `targetSdk 37`, `minSdk 26`.

## Installation

1. Open the repository **Releases** page.
2. Download `FoodScanner-0.3-beta.apk`.
3. Open the file on the phone.
4. If Android asks for permission, enable **Install unknown apps** for Chrome or
   for the file manager.
5. If the Play Protect warning appears, choose **Install anyway**: the APK is
   signed with the debug key, it is not published on the Play Store.
6. Open **Food Scanner** and wait for the first start: the Python assets are
   copied into the app private storage.

There is no need to install Python, Termux or anything else.

## How to use it

- **Barcode**: type the code and press **Analyze**.
- **Offline demo**: try a product without a network.
- **Camera**: the button opens the camera or the gallery. Automatic barcode
  reading depends on the WebView `BarcodeDetector` support; if it is not
  available, type the code by hand.
- **Result**: score, components, additives, nutrients and explanations.

Looking up a new product requires Internet and Open Food Facts. The demo and the
scoring of an already downloaded JSON work offline.

## What is not included

- Sending photos to Open Food Facts is not configured in the APK: there are no
  credentials inside the package. The **+ Add photo** button is therefore disabled
  server-side.
- There is no analytics, advertising or account.
- The product cache lives in the app private storage and is cleared by
  uninstalling it.

## Android 17 and installing from an APK

Android 17 is API 37. The APK is already built and targeted at API 37.

Installing an APK downloaded from GitHub needs the usual **Install unknown apps**
consent. Google's developer verification applies from 30 September 2026 only to
installations from some stores in Brazil, Indonesia, Singapore and Thailand; the
global rollout is expected in 2027. If Android shows the advanced flow for
unverified developers in the future, you can allow the installation from the
developer options or use `adb install` (which stays available).

## Build

The automatic build is in the workflow `.github/workflows/android-apk.yml`.

Local requirements:

- JDK 17;
- Android SDK 37 and Build Tools 36.0.0;
- Gradle 9.6.0.

```bash
cd android
gradle :app:assembleDebug
```

The APK is written to:

```text
android/app/build/outputs/apk/debug/app-debug.apk
```

The `stageFoodScannerAssets` Gradle task automatically copies `engine/`, `ui/` and
`data/` into the APK assets: there are no duplicated copies to maintain by hand.

## Signing and updates

The APK is signed with the debug key generated by the build. It is fine for a
personal installation and for sideloading, not for the Play Store. If you change
the signature in the future, Android may refuse the update over the existing app:
in that case uninstall the old version and install the new one.
